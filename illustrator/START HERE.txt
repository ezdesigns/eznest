EZ Nest Illustrator pilot - draft build only

For Codex-assisted setup on a separate design PC, start with START-CODEX.md at
the repository root. That guide uses a temporary source launch and separate
test data/output folders, without installing a service. The packaged-install
steps below are an alternative, not required for that source pilot.

1. Install the matching draft eznest-setup.exe from the PR's Windows installer
   artifact. Do not replace the frozen rc.4 shop-test installation.
   Use a separate test Windows PC for this draft.
2. Start eznest on this PC, with localhost port 8765. Finish first-run setup.
   For the pilot choose an empty TEST output folder, not the live ONYX folder.
3. In Illustrator, open a COPY of a real kit and save it. Select the complete
   production artwork and its cut paths.
4. Run "Nest in eznest.jsx" through File > Scripts > Other Script. Keep all
   four files together: Nest in eznest.jsx, Prepare for EZ Nest.jsx,
   EZ Nest Settings.jsx and bridge-core.js.
   For a permanent menu entry, copy this folder's files to Illustrator's
   Presets/<language>/Scripts folder and restart Illustrator. Run File > Scripts
   > Nest in eznest. This is a script menu action, not an installed plugin panel.
5. On the first run, choose your existing approved ONYX Adobe PDF preset,
   Regular material, printable width and EXISTING bleed. These settings are saved
   per Windows user. Run EZ Nest Settings.jsx to change them. If a saved preset
   is removed or settings are damaged, setup opens again; no substitute is chosen.
6. Later runs need no setup dialog: finish your colors/bleed, save the source,
   select complete parts, and run Nest in eznest. It creates a separate production
   document with print, thru-cut and kiss cut layers and exports your saved preset.
   The original document is reactivated and never overwritten.
7. The browser opens and loads the handoff automatically into an empty workspace.
   Choose sets, inspect every piece, scale, colors and cut path, then Review and
   send. Shop setup must be finished first. An existing job is never automatically
   replaced; finish it or explicitly load and confirm replacement. Reloading the
   page preserves a reviewed/sent job. Retry is available if loading fails.
8. Compare the resulting artwork.pdf against your normal production PDF in
   Illustrator and ONYX before any physical production.

SUPPORTED PREPARATION
Copies selected artwork into a separate document; preserves its object structure
and scale; moves separate unfilled cut strokes to the specified output layers;
maps those strokes to CutContour_Thru-cut / CutContour_Kiss-cut spots; and exports
with an existing Adobe PDF preset you explicitly choose once and can change later. All other color handling
comes from that PDF preset. The original source is never saved by the script.

Cut strokes must be on source layers named thru-cut or kiss cut, or use the
recognized CutContour_Thru-cut / CutContour_Kiss-cut spots. Generic CutContour
requires one of those source layers. Conflicting names, filled cut paths and
clipping paths used as cuts are rejected. Keep the artwork mask separate from
the cut stroke. Parent/child selections are counted once. The production copy fits a fresh artboard around all copied object bounds, including existing bleed and 2 mm clearance. Original objects are not scaled.

NOT YET AUTOMATED
Template registration, clip-group repair, new bleed generation, production
color substitutions, Chrome/Holographic rules, or returning the final nest to
Illustrator automatically. The exported PDF can be opened in Illustrator.
This is a handoff/preparation pilot, not full Nest Pro feature parity.

LOCAL DATA
Illustrator saves only PDF preset, material, width and existing bleed under
Folder.userData/eznest/illustrator-settings.json. Sets reset to 1 for every new
export. No tokens, source paths or artwork are saved in these preferences.
The bridge requires eznest on the SAME PC as Illustrator, at 127.0.0.1:8765;
a browser-only LAN workstation cannot use this local bridge yet.
The app stores a PDF handoff and metadata under its data directory's illustrator
folder. The source path is hashed; it is not stored in the handoff manifest.
Each export gets a handoff ID. Repeating a browser calculation for that handoff
and production settings counts once in local activity; changing quantity or
production settings creates a distinct workload observation. Running this script
again is a NEW attempt, even for identical artwork. No OUTPUT uploads exist.
Handoff PDFs are retained until you remove them with the app stopped. Workload
events follow the existing 90-day policy. Illustrator leaves its temporary export
under the OS temp folder's eznest-illustrator subfolder.

VALIDATION LIMIT
The bridge protocol and browser flow are automated-testable. Actual Illustrator
host behavior, your PDF preset and your production files require the shop pilot.
The current script changes still need a live Illustrator acceptance run.

WHOLE DESIGN
Run Nest whole document.jsx to copy the visible, unlocked document artwork without selecting every item first. It uses the same saved PDF preset and preparation checks. Hidden and locked source objects are excluded; finish specialty colors in Illustrator. Keep all companion scripts together. A PDF-compatible AI file can also be dropped into the browser directly, but PDF-page clipping still requires a source export containing the complete art.
