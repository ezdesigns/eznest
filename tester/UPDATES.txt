WILL CODE CHANGES APPEAR AUTOMATICALLY?
No. This kit is a portable snapshot. Editing or pushing source code does not
change an installed tester copy. Automatic update checks are disabled here.
Codex does not receive your new code or keep testers synchronized by itself.

FOR THE ORGANIZER
Change the source, run the appropriate checks, build a new Windows app, and
package a new verified tester ZIP. Send testers that ZIP and its checksum.
Give every kit a unique ID and describe what changed. A guide-only kit may
contain the same app; compare KIT.json appBuildId and BUILD.json exeSha256.
Do not treat a wrapper rebuild as a new application build.

FOR THE TESTER
1. Get the next ZIP from your organizer; extract it to a NEW folder.
2. For help, open that folder in Codex and paste CODEX UPDATE PROMPT.txt.
3. Finish current work and use STOP Shop Test.cmd from the RUNNING kit's folder.
4. While stopped, copy %LOCALAPPDATA%\eznest-shop-trial to a dated backup.
5. Run START EZ NEST.cmd from the new folder. Keep the old folder as a fallback.
6. Check settings, saved work and TEST Output. Use the same browser for material
   presets. Keep backups; do not delete or overwrite original artwork.

If only the guide/prompts changed and the app/runtime/scripts are identical,
you can use the new instructions without restarting the existing app.

AUTOMATIC UPDATES LATER
The source includes an installer-based update mechanism, but this unsigned
portable trial does not use it. Enabling a supported rollout requires trusted
signed releases, a configured release feed, an initial supported installation,
and real Windows upgrade/rollback tests. It must preserve work and settings and
verify the publisher before installation. This kit does not enable that rollout
or authorize replacing the protected shop installation.
